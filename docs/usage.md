# macOS installer and DLC packer

## Interactive installer: Wir Schaffen DLC

The easiest workflow is the branded terminal interface. Quit Civilization V,
then run this from the repository directory:

```sh
./wir-schaffen-dlc.command
```

It automatically looks for the normal Steam installation at:

```text
~/Library/Application Support/Steam/steamapps/common/Sid Meier's Civilization V/Civilization V.app
```

It reads mods from:

```text
~/Library/Application Support/Sid Meier's Civilization 5/MODS/
```

and standalone maps from:

```text
~/Library/Application Support/Sid Meier's Civilization 5/Maps/
```

Select mods with numbers, comma-separated numbers, ranges, or `all`. For
example, `1,3-5` selects entries 1, 3, 4, and 5. The installer packages and
validates every selection in a temporary directory before touching the game.
If any build fails, nothing is installed.

When run in an interactive terminal, the landing screen uses the terminal's
alternate buffer. Move with **↑/↓** (or **J/K**), press **Enter** to launch the
highlighted program, and press **Q** or **Escape** to leave. The cursor and
original terminal contents are restored on normal exit and errors. Redirected
input and automation flags continue to use the line-oriented fallback.
The alternate buffer remains open after program selection: path choices,
downloads, packaging progress, typed confirmations, cancellation, completion
and errors all stay inside the themed interface. Press **Enter** or **Q** on
the final screen to return to the original terminal contents.
During work, a fixed progress panel identifies the active Download, Verify,
Package or Install phase. Workshop downloads report the current source,
percentage, received/total bytes and transfer speed. Verification, packaging
and transactional installation use the same panel for per-item completion;
the diagnostic log remains visible underneath it.
The interactive screen applies the approved mockup's gentle-yellow surface and
24-bit Bauhaus palette to the complete terminal grid, including otherwise
unused rows and columns, so its appearance does not depend on the active
Terminal profile. Set `NO_COLOR=1` to retain the terminal's normal colors.
The temporary terminal background override also covers Terminal.app's inset
margin and is restored automatically whenever the launch screen closes.

Choose option 1, **AngelaDMerkel's Very Best Mods**, at the top-level menu,
or use `--very-best-mods`. This downloads and packages exactly:

- Brotherhood of Steel v2
- Really Raging Barbarians v1
- Mass Effect Civilizations v7
- Workable Mountains v2
- Future Worlds v6
- Corporations (Brave New World) v1
- Really Advanced Setup v15

[Workable Mountains v2](https://steamcommunity.com/sharedfiles/filedetails/?id=233614126)
is the Civilization V edition (Workshop item `233614126`, Steam app `8930`).
The preset verifies its ModBuddy ID and version before packaging it.
Really Advanced Setup is downloaded from the author's official
Steam Workshop mirror because CivFanatics protects its binary endpoint with a
browser challenge.

Standalone builds include the root certificates needed for HTTPS downloads.
To check the connection and all seven Workshop identities without discovering
the game or installing files, run:

```sh
./wir-schaffen-dlc --check-downloads
```

This preset is all-or-nothing and exclusive. It cannot be combined with
`--select`, `--map`, or any other package generated by Wir Schaffen DLC. While
one of its members is installed, the regular packaging mode refuses to add
mods. This lock applies only to tool-generated packages; normal Firaxis DLC is
not modified. Every `pack-report.json` records all source URLs, Workshop
content IDs, sizes, and SHA-256 hashes.

Choose option 3, **Install AngelaDMerkel's map patch**, or pass
`--excogitare-patch` to install Excogitare compatibility without packaging an
individual map. The program performs one transaction with two parts:

- an authenticated DLC package registers Extreme `180x94` with 20 major and
  20 minor slots, and Colossal `170x110` with 22 major and 22 minor slots;
- the supported macOS executable receives the signature-checked, reversible
  divisor and projection-normalization guard.

Excogitare's Tall, Wide and Square geometries remain ordinary rectangular
Civ5Map files and need no separate database type. Needle, Ribbon, Pin and
String can exceed ordinary axis/aspect behavior and use the engine guard. The
patch addresses the known database lookup, zero-divisor and non-converging
projection failures; it cannot guarantee that unsafe maps remain within Civ
V's memory, minimap, pathfinding or late-game limits.

The compatibility DLC may coexist with Very Best Mods. Every macOS multiplayer
participant using the custom size or geometry must install the same patch.

Choose option 4, **Restore stock Civilization V**, or pass `--restore-stock`
to reverse every persistent change made by Wir Schaffen DLC. Before touching
the game it authenticates each `Civ5MP - …` package against its generated
report, verifies that the executable is either the supported stock build or a
known guarded build with an exact original backup, and validates the cache
targets. It then performs one rollback-capable transaction:

- remove the authenticated generated DLC folders;
- restore and SHA-256 verify the original Civilization V executable;
- invalidate `Civ5CoreDatabase.db`, `Civ5DebugDatabase.db`,
  `Civ5ModsDatabase.db`, and `Localization-Merged.db` so Civ V rebuilds them;
- remove the no-longer-needed verified engine backup.

Official Firaxis DLC, saved games, user MODS and Maps, preferences,
screenshots, user history and other cache databases are preserved. If an
apparent generated folder is incomplete or fails authentication, restoration
stops rather than risking unrelated content. Changes made manually or by other
tools remain outside this ownership boundary; use Steam's file verification
for an unknown executable.

The generated folders are installed beneath the application bundle's
`Contents/Assets/Assets/DLC/` directory. Matching packages are not overwritten
without confirmation, and a failed multi-package copy is rolled back.

When two or more packed mods use `InGameUIAddin`, the installer does not let
their separate `UI/InGame.lua` files compete by DLC load order. It builds a
single priority **Wir Schaffen DLC Shared UI Bridge** covering both installed
and newly selected packages. Each add-in is loaded in a separate Lua context.
The complete virtual file namespace is checked first, and different files with
the same virtual name stop the transaction with a clear error.

For an unusual Steam library or user-data location, pass the paths explicitly:

```sh
./wir-schaffen-dlc.command \
  --game-app "/Volumes/Games/steamapps/common/Sid Meier's Civilization V/Civilization V.app" \
  --user-data "$HOME/Library/Application Support/Sid Meier's Civilization 5"
```

Useful automation and diagnostic options are:

```text
--select 1,3-5   preselect mod numbers
--select all     select every discovered mod
--very-best-mods download and package the exclusive curated collection
--excogitare-patch install Excogitare custom-size and geometry compatibility
--restore-stock    remove verified tool changes and restore stock Civ V
--dry-run        package and validate without installing
--replace        permit replacement of matching tool-installed packages
--yes            skip the final install confirmation
--map PATH       also offer a standalone .Civ5Map outside the Maps directory
```

`--yes` does not imply `--replace`; updating an existing package requires both
options. The script does not request administrator privileges.

Non-interactive validation of the curated sources without installation:

```sh
./wir-schaffen-dlc.command --very-best-mods --dry-run
```

Validate the Excogitare patch and local executable without changing either:

```sh
./wir-schaffen-dlc.command --excogitare-patch --dry-run
```

Preview the complete stock rollback without changing the installation:

```sh
./wir-schaffen-dlc.command --restore-stock --dry-run
```

## Direct packer

`civ5_dlc_packer.py` converts a ModBuddy mod directory into a
Civilization V DLC directory. This is useful on the native macOS build, where
the MPPatch native runtime hook is not available.

The result is deliberately a folder, not an installer. It is inspectable,
easy to remove, and can be copied unchanged to every multiplayer participant.

## Colossal and extreme standalone maps

Use `--map-file` to package a WorldBuilder map directly. The packer validates
the v11/v12 header and eight-byte plot records, refuses maps beyond the
file-format limit of 32,768 plots, and copies the source without modification.
For an unknown world identifier it adds a DLC `Worlds` row cloned from Huge,
with the map's exact width, height, and player count.

```sh
python3 civ5_dlc_packer.py --map-file \
  "/path/to/map.Civ5Map" \
  "build/packed-dlc/Map Test" \
  --base-db "$HOME/Library/Application Support/Sid Meier's Civilization 5/cache/Civ5CoreDatabase.db"
```

This fixes the missing database/UI lookup for identifiers such as
`WORLDSIZE_COLOSSAL` and `WORLDSIZE_EXTREME`; it does not resize the geography.
When the interactive installer selects an Excogitare custom size, a map with
an axis above 255 tiles, or a map at least 8:1 in aspect, it also applies
reversible guards for the native engine's zero divisor and unbounded
projection-normalization loops. Extreme maps remain experimental beyond
initial loading; the build report records a warning and the exact map SHA-256.

## Future Worlds v6 trial

The packer recognizes Future Worlds v6 and translates its six SQL actions into
DLC-compatible XML. It also:

- materializes the SQL-generated mutant art and fungal-growth resource rows;
- moves the Future Tech node and inserts the Future Worlds era in the intended
  order;
- removes the custom `Eras.SplashScreen` database column and rewrites the era
  popup to use a static mapping;
- injects `FutureLua.lua` through the active Brave New World `InGame.lua`;
- detects duplicate virtual filenames, deduplicates identical files, and
  renames/relinks different files safely.

Run from the repository root:

```sh
python3 civ5_dlc_packer.py \
  "$HOME/Library/Application Support/Sid Meier's Civilization 5/MODS/Future Worlds (v 6)" \
  "build/packed-dlc/Future Worlds (v 6)" \
  --base-db "$HOME/Library/Application Support/Sid Meier's Civilization 5/cache/Civ5CoreDatabase.db" \
  --game-assets "$HOME/Library/Application Support/Steam/steamapps/common/Sid Meier's Civilization V/Civilization V.app/Contents/Assets/Assets" \
  --ui-set Expansion2
```

The output includes a `.Civ5Pkg`, `Files` and `UI` directories, translated
database XML, and `pack-report.json`. The report records the source identity,
the deterministic DLC UUID, all translations, and known omissions.

## Corporations v1 trial

Corporations adds 16 columns to eight core game tables through SQL. A DLC
cannot safely perform those late schema changes, so its compatibility compiler:

- creates eight `Corporation*Settings` sidecar tables;
- moves the SQL values and custom XML fields into keyed sidecar rows;
- retains the mod's native `Corporations` and `CorporationSettings` tables;
- rewrites the affected Lua configuration lookups and embeds their values into
  every isolated Civ V Lua context that uses them;
- preserves the original art, Lua entry point, and Brave New World UI
  overrides.

Build it with:

```sh
python3 civ5_dlc_packer.py \
  "$HOME/Library/Application Support/Sid Meier's Civilization 5/MODS/Corporations (Brave New World) (v 1)" \
  "build/packed-dlc/Corporations (Brave New World) (v 1)" \
  --base-db "$HOME/Library/Application Support/Sid Meier's Civilization 5/cache/Civ5CoreDatabase.db" \
  --game-assets "$HOME/Library/Application Support/Steam/steamapps/common/Sid Meier's Civilization V/Civilization V.app/Contents/Assets/Assets" \
  --ui-set Expansion2
```

The generated package is structurally validated, but Corporations persists
state through `Modding.OpenSaveData()`. A multiplayer host/client session and a
save/reload cycle are required before calling its runtime behavior verified.

To install the trial package, quit Civilization V and copy the complete output
directory into the app's DLC directory:

```sh
ditto \
  "build/packed-dlc/Future Worlds (v 6)" \
  "$HOME/Library/Application Support/Steam/steamapps/common/Sid Meier's Civilization V/Civilization V.app/Contents/Assets/Assets/DLC/Future Worlds (v 6)"
```

Remove that exact `DLC/Future Worlds (v 6)` directory to uninstall it. Do not
enable the original Future Worlds copy in the Mods menu while testing the DLC.

Packed DLC is started from the ordinary **Single Player** or **Multiplayer**
menus. Do not select the same source mod through the **Mods** menu: Civ V will
then load both copies, producing duplicate database rows and registering Lua
events twice. The installer prints this warning after every installation.

## Multiplayer requirements

Every player needs a byte-identical packed DLC folder and the same Civ V DLC/
expansion set. The Future Worlds compiler uses the supplied core database to
materialize SQL `SELECT` results, so differing game data can cause database
checksums or gameplay to diverge.

Start with a new multiplayer save. A DLC changes the game database at startup,
so adding or removing it from an existing save is unsafe.

## Current boundaries

The generic path supports database XML, imported assets, localization XML,
imported leader scenes, `.Civ5Map` files, Lua map scripts, and
`InGameUIAddin` Lua entry points. A GameData XML entry point with a same-name
Lua companion is also recognized. Arbitrary SQL is rejected unless an explicit
compatibility compiler exists; silently dropping SQL would produce a corrupt
or incomplete mod. Other ModBuddy action and entry-point types are rejected
with a clear error.

Future Worlds' runtime SQL triggers are not retained. Their effects for the
current Brave New World database are materialized in XML instead. The
Enlightenment Era integration is included only when those records are present
in the database passed with `--base-db`.

Run the packer tests with:

```sh
python3 -m unittest discover -s tests -v
```

The [local compatibility matrix](compatibility.md) records the
results from packing all 15 mods installed on the development Mac.
